1 · KAPAZITÄT DES INTERNETANSCHLUSSES
---------------------------------------------------------------------

Durchsatz messen (zwei Terminals)
KUNDE steht im Internet und erreicht TechTrade über die öffentliche
Adresse 203.0.113.1. R1 leitet Port 5201 an SRV-WEB weiter.

Auf SRV-WEB:
iperf3 -s
# -s = Server: wartet auf Messungen (TCP-Port 5201)
# läuft, bis Sie Ctrl+C drücken

Auf KUNDE:
iperf3 -c 203.0.113.1 -t 15
# -c = Client: misst gegen den Server hinter 203.0.113.1
# -t 15 = 15 Sekunden lang senden
# KUNDE sendet -> Richtung Internet zu TechTrade = DOWNLOAD von TechTrade
# Massgebend ist die Zeile "receiver" ganz unten (Spalte Bitrate)
iperf3 -c 203.0.113.1 -t 15 -R
# -R = umgekehrte Richtung: SRV-WEB sendet zu KUNDE = UPLOAD von TechTrade
# Jede Richtung zweimal messen, den besseren Wert eintragen

Während der Messung: Grafana -> Kapazität Shop -> Panel "Internetanschluss (R1 eth3)"
# Upload = Verkehr von TechTrade ins Internet, Download = aus dem Internet
# Das Panel zeigt ein Mittel über 1 Minute: der Wert steigt verzögert
# und erreicht bei 15 s Messdauer nicht ganz den iperf3-Wert.

Traffic Shaping, Rate Limiting und Destination NAT anzeigen
Auf R1:
show configuration commands | match qos
# "qos policy shaper <NAME> bandwidth ..."   = Traffic Shaping (puffert)
# "qos policy limiter <NAME> ... bandwidth"  = Rate Limiting (verwirft)
# "qos interface <ethX> egress <NAME>"       = gilt für das, was R1 hinaus sendet
# "qos interface <ethX> ingress <NAME>"      = gilt für das, was bei R1 ankommt
show configuration commands | match "nat destination"
# Destination NAT: welche Ports der öffentlichen Adresse wohin weitergeleitet werden

Messdaten öffnen
Auf SRV-MON:
localc ~/lab/kapazitaet.xlsx &
# localc = LibreOffice Calc; & = im Hintergrund, das Terminal bleibt frei
# Blätter (Reiter unten): Internet, Prognose, Shop
# Alle Werte sind berechnet. Sie schreiben keine Formeln.

3 · LASTTEST VOR DER SKALIERUNG
---------------------------------------------------------------------

Ziellast eintragen
Auf KUNDE:
cd ~/lab/k6
nano weihnachten.js
# Zeile:  const ANFRAGEN_PRO_SEKUNDE = 1;
# Die 1 durch Ihre Ziellast ersetzen
# Speichern: Ctrl+O, Enter · Beenden: Ctrl+X

Lasttest starten (dauert 2 Minuten)
Auf KUNDE:
cd ~/lab/k6
sudo docker run --rm -i grafana/k6:1.3.0 run - < weihnachten.js
# grafana/k6 = Programm k6 vom Hersteller Grafana Labs (nicht Grafana selbst)
# docker run --rm = k6 als Container starten, nach dem Test löschen
# -i = Eingabe an den Container weiterreichen
# run - = Testskript von der Eingabe lesen; < weihnachten.js = diese Datei
# Der Test endet nach 2 Minuten (duration im Skript), dann endet der Container
#
# Zusammenfassung am Schluss lesen:
#   THRESHOLDS            Zielwerte; Häkchen = erfüllt, Kreuz = verletzt
#   http_req_duration     Antwortzeit; p(95)=... ist das 95. Perzentil
#   http_req_failed       Anteil fehlgeschlagener Anfragen
#   http_reqs             Anzahl Anfragen und tatsächlich erreichte Rate (.../s)
# Meldungen "request timeout" oder Status 504 während des Tests:
#   Der Shop antwortet nicht innerhalb der Wartezeit des Reverse Proxys.

Während des Tests beobachten
Grafana -> Kapazität Shop: CPU pro Container, Antwortzeit, Internetanschluss
# Gestrichelte Linien = CPU-Limit der Applikationsserver
# Grafana läuft auf SRV-MON (Firefox), der Lasttest auf KUNDE
# Panel "Antwortzeit" = Stichprobe (1 Anfrage alle paar Sekunden von SRV-MON).
# Massgebend für L1 und L2 ist die Zusammenfassung von k6 (misst jede Anfrage).
Mailpit: Mails des Monitorings

Live-Ansicht der Container (optional)
Auf SRV-WEB:
sudo docker stats
# CPU % und Arbeitsspeicher pro Container, laufend aktualisiert; Ctrl+C beendet
# CPU % bezieht sich auf eine ganze CPU: ein Container mit Limit 0.25 CPU
# zeigt höchstens etwa 25 %

4 · PLATTFORM HORIZONTAL SKALIEREN
---------------------------------------------------------------------

Reihenfolge: zuerst die Compose-Datei (app3 starten),
danach die nginx-Konfiguration (neu laden).

Sicherungskopien anlegen (Rückweg)
Auf SRV-WEB:
cd /opt/shop
sudo cp compose.yaml compose.yaml.orig
sudo cp nginx/default.conf nginx/default.conf.orig

Compose-Datei erweitern
Auf SRV-WEB:
cd /opt/shop
sudo nano compose.yaml
# Speichern: Ctrl+O, Enter · Beenden: Ctrl+X
# Einrückung mit Leerzeichen, nie mit Tabulator.
# Ein neuer Dienst braucht alles, was ein bestehender gleichartiger Dienst
# hat: Image, Umgebungsvariablen, Secret, Netze, Abhängigkeiten, Neustart.

----- Baustein A: NEUER Dienst unter services: (gleich eingerückt wie app2) -
# Tipp: den ganzen Block app2 kopieren und anpassen
  <dienst>:                      # Name des Dienstes
    image: <image>:<version>
    environment:
      <VARIABLE>: <wert>
    deploy:
      resources:
        limits:
          cpus: "<anteil>"       # Anteil CPUs, "1.0" = eine ganze CPU
          memory: <zahl>M        # Arbeitsspeicher in MB

----- Baustein B: im BESTEHENDEN Dienst proxy unter depends_on: ergänzen -
      - <dienst>                 # proxy startet erst nach diesem Dienst
---------------------------------------------------------------------

Compose-Datei prüfen und übernehmen
Auf SRV-WEB:
cd /opt/shop
sudo docker compose config -q
# config = Datei prüfen; -q = nur Fehler anzeigen (keine Ausgabe = gültig)
sudo docker compose up -d
# up -d = Stack im Hintergrund an die Datei anpassen:
#         startet nur, was neu oder geändert ist
sudo docker compose ps
# Status aller Dienste des Stacks

nginx-Konfiguration erweitern
Auf SRV-WEB:
cd /opt/shop
sudo nano nginx/default.conf
# default.conf wird im http-Block der Hauptdatei nginx.conf eingebunden.
# proxy_cache_path und upstream stehen ausserhalb von server { ... }.
# Grössen z. B. 5m, 100m, 1g · Zeiten z. B. 30m, 1h
# keys_zone = Name und Arbeitsspeicher für die Schlüssel der Einträge
# inactive  = so lange nicht abgerufen -> Eintrag wird entfernt
# Anteil eines Servers = sein Gewicht ÷ Summe aller Gewichte; ohne weight gilt 1
# $upstream_cache_status = HIT (aus dem Cache), MISS, EXPIRED ...
# nginx wählt die location mit dem längsten passenden Pfad

----- Baustein A: NEUE Zeile, ganz oben (vor upstream) --------------
proxy_cache_path <verzeichnis> levels=1:2 keys_zone=<zone>:<grösse> max_size=<grösse> inactive=<zeit>;

----- Baustein B: im BESTEHENDEN Block upstream shop_app ergänzen -----
# bestehende Zeilen um weight=<zahl> ergänzen, eine Zeile neu:
    server <dienst>:<port> weight=<zahl>;

----- Baustein C: NEUER Block innerhalb server { }, nach location / { } -
    location <pfad> {
        proxy_pass http://shop_app;
        proxy_cache <zone>;
        proxy_cache_valid <status> <zeit>;
        add_header <Header-Name> $upstream_cache_status;
    }
---------------------------------------------------------------------

nginx-Konfiguration prüfen und neu laden
Auf SRV-WEB:
cd /opt/shop
sudo docker compose exec proxy nginx -t
# exec proxy = Befehl im laufenden Container proxy ausführen
# nginx -t = Konfiguration prüfen ("syntax is ok", "test is successful")
sudo docker compose exec proxy nginx -s reload
# -s reload = neue Konfiguration laden, ohne laufende Verbindungen zu trennen

Verteilung prüfen
Auf SRV-WEB:
curl -kI https://localhost/
# -I = nur die Antwort-Header anzeigen; -k = selbstsigniertes Zertifikat akzeptieren
# Zeile X-Backend = welcher Applikationsserver geantwortet hat
# Befehl rund 8-mal wiederholen (Pfeil nach oben, Enter):
# app3 sollte etwa jedes zweite Mal antworten, app1 und app2 je etwa jedes vierte Mal

Cache prüfen
Auf SRV-WEB:
curl -kI https://localhost/static/shop.css
# zweimal ausführen und die Zeile X-Cache-Status vergleichen:
# MISS = vom Applikationsserver geholt, HIT = aus dem Cache
curl -kI https://localhost/
# Shop-Seite: keine Zeile X-Cache-Status = wird nicht zwischengespeichert

Shop von KUNDE aus über HTTP und HTTPS (öffentliche Adresse)
Auf KUNDE:
curl -I http://203.0.113.1/
curl -kI https://203.0.113.1/
# erste Zeile: HTTP/1.1 200 OK = in Ordnung

Logs bei Problemen
Auf SRV-WEB:
cd /opt/shop
sudo docker compose logs --tail 20 proxy
sudo docker compose logs --tail 20 app3
# --tail 20 = nur die letzten 20 Zeilen

Rückweg (falls nötig)
Auf SRV-WEB:
cd /opt/shop
sudo cp compose.yaml.orig compose.yaml
sudo cp nginx/default.conf.orig nginx/default.conf
sudo docker compose up -d --remove-orphans
# --remove-orphans = Container entfernen, die nicht mehr in der Datei stehen
sudo docker compose exec proxy nginx -s reload
